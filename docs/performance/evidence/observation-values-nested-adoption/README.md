# Strict nested ingestion adoption evidence

See [the decision report](../../observation-values-nested-adoption.md).

`manifest.json` records final source hashes and matched before/after dependency closures. `summary.csv` contains 60 final main timing processes, three fresh-process repeats of ten workloads per route. `joined-manifest.json` and `joined-summary.csv` add 12 processes for the real joined-load DTO contract using the exact same final Core with a separately matched harness closure. `initial-manifest.json` and `initial-summary.csv` preserve the 60-process first integration. `enum-manifest.json` and `enum-summary.csv` preserve 60 processes after shrinking boxed enumeration, before the canonical-ordering integration. `broad-manifest.json` and `broad-summary.csv` preserve the broadly enabled candidate; the final production plan excludes records through eight fields. `tested-core-il.json` verifies tested/frozen method bodies; it does not compare the old and integrated implementation. `verification.json` records test/conformance counts. Raw reports, logs, source snapshots for all phases and packaging templates are SHA-256 indexed in `raw-reports.tar.gz` / `raw-reports-index.json`.

The before Core is the frozen build from the preceding ordinal-validation experiment (source commit recorded in the manifest; binary informational version predates that source commit). Its SHA matches that experiment's manifest. The after closure uses current production integration. Every other runtime DLL/config is identical within each matched pair. DTO fixtures and the benchmark executable are therefore identical in each comparison.

Build/freeze the preceding source revision for the before Core.
