# COH-135 implementation review

[COH-135](https://linear.app/cohesive-ari/issue/COH-135) qualifies a configured integration
against an actual resource offer and retains that decision with the existing ingestion
Requests and Process. The historical-data case is exercised both in Cohesive examples and
Ito's Tiingo adapter. This work includes the authoring/connection/configuration
prerequisites from [COH-133](https://linear.app/cohesive-ari/issue/COH-133) and
[COH-134](https://linear.app/cohesive-ari/issue/COH-134).

## Semantic authority and invariants

Fluent source lowers deterministically to canonical documents. Existing native Request and
Process definitions remain the protocol authority. Configuration owns precedence and policy;
Integrations interprets domain eligibility; adapter/domain interpreters understand property
predicates. Ito owns market-data validation and composes these shared mechanisms at acquisition.

A new effect requires fresh qualification and, for scoped admission, current mandatory-policy
permission. Reconciliation uses original retained evidence and does not query today's policy or
renew evidence. Unknown acquisition is never permission to refetch. Incomplete source coverage
cannot advance the ledger. A known local denial retains a no-call result.

Audit checks original qualification lineage and validity at the recorded time, reproduces saved
policy diagnostics, and rejects omitted required evidence or contradictory local-denial outcomes.
It does not interpret arbitrary predicates or independently authenticate historical evidence issuers.

## Review boundaries and tradeoffs

- Capability fixtures in Cohesive examples are offline conformance inputs. Real Tiingo offers describe
  the bound implementation; live access, availability and complete interval coverage remain runtime
  obligations. There is no remote entitlement attestation or universal predicate solver.
- Ito's local policy file contains a coherent scope/contribution/grant snapshot. Fluent sources
  generate its canonical documents. The host must protect the file and supplies publication authority.
  An authoritative empty set means no restrictions; unavailable reads throw.
- The CLI catalog currently contains its Tiingo profile/default-account connection. Broader catalogs
  are supported by host composition but are not a new CLI configuration surface in this slice.
- Dispatch audit is retained with the acquisition result, not in a separate pre-dispatch journal.
  Crashes before result retention preserve conservative ambiguity. No distributed policy consistency
  or hardware durability certification is claimed.
- The one-day CLI qualification lifetime is explicit host policy, not a provider SLA.
- Current acquisition payloads use v2; no backward-compatibility reader was introduced.
- Canonical IR remains derived. Runtime clients, credential resolution and policy callbacks do not
  enter it. New document-kind constants expose existing schema identities without duplicating them.
- No new external package or parallel execution/policy framework was introduced. The optional local
  co-development targets remain temporary until shared packages are published.

## Validation and delivery

Final selected suites passed: 247 framework integration/contract tests, 19 integration examples,
152 Ito integration/EOD tests, and 29 CLI tests (447 total). These are focused conformance suites,
not a claim that every test in either repository was run. Unrelated existing framework test-project nullable warnings
remain; no warnings were intentionally suppressed.

Changes span coordinated Cohesive and Ito branches. This review is not a claim
of merge, deployment, live provider testing or completed production evidence trust. The next delivery
step is review of the combined authoring/configuration/qualification change and a coordinated package
revision for Ito; production evidence trust and broader deployment requirements should remain explicit
follow-up scope rather than silently expanding this implementation.
